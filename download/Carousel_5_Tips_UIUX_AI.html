// UI/UX Design · Part 1
Design Systems
Are Not Optional
01
Build Design Tokens First
Before drawing a single screen, define colors, typography scale, spacing, and shadows as tokens. Figma Variables + Tailwind config in sync = consistency on autopilot.
→ Action: Create tokens.json before wireframes
02
Auto Layout > Manual Padding
Learn Figma Auto Layout deeply. Components built with Auto Layout respond to content changes — no more "design broke when copy changed" reviews.
→ Action: Refactor 1 old component to Auto Layout today
03
Accessibility = Free Market Expansion
WCAG 2.1 AA isn't just compliance — it's 15% more users who can actually use your product. Contrast ratios, focus states, semantic HTML.
→ Action: Run axe DevTools on your latest project

// UI/UX Design · Part 2
Test With 5 Users
Not 50
5
users reveal 85% of usability problems.
Source: Nielsen Norman Group.
Don't wait for "perfect" — test early, iterate fast.
04
Prototype Before You Code
Figma's interactive prototype + 5 user tests = weeks saved in development. A clickable prototype catches flow issues that wireframes can't.
→ Action: Prototype the next feature before sprint planning
05
Micro-interactions = Delight
Hover states, loading animations, success toasts — these aren't "nice to have". They're the difference between a tool people use and one they love.
→ Action: Add 3 micro-interactions to current sprint

// AI Engineering · Part 1
Prompt Engineering
Is Real Engineering
06
Separate System & User Prompts
System prompt = persona & rules. User prompt = the actual query. Mixing them = unpredictable output. Keeping them separate = consistent, testable behavior.
// Bad messages: [{ role: 'user', content: 'You are a tutor. Explain...' }] // Good messages: [ { role: 'system', content: tutorSystemPrompt }, { role: 'user', content: userQuery } ]
07
Cache Aggressively · Save 70% on Costs
In TRADIX, I implemented two-layer caching (memory + persistent). Result: 70% fewer API calls, 60% faster response, 80% lower cost. Same model, smarter retrieval.
→ Action: Add Redis or in-memory cache to your next LLM call

// AI Engineering · Part 2
RAG > Fine-tuning
(90% of the time)
08
Use RAG for Domain Knowledge
Fine-tuning is expensive, slow, and hard to update. RAG (Retrieval-Augmented Generation) lets you swap docs in seconds. For 90% of use cases, RAG wins.
Fine-tuning
$$$ · Hours to retrain · Hard to debug · Hallucination risk on updates
RAG
Free · Seconds to update · Debuggable · Source-attributable
09
Run ML Inference on Background Thread
On mobile (Flutter/React Native), never block the UI thread for ML. Use Isolate (Flutter) or Web Worker (Web). Users won't tolerate jank for AI features.
// Flutter: TFLite on Isolate Future<Prediction> predict(File image) async { return await compute(_runInference, image.path); // UI stays 60fps during inference }

// Full-Stack · MLOps
Automate ML Retraining
From Day One
10
CI/CD for ML = MLflow + GitHub Actions
Don't manually retrain. Set up a weekly cron job that runs mlflow run MLProject --env-manager=local via GitHub Actions. Models stay fresh, drift drops 50%.
# .github/workflows/retrain.yml on: schedule: [{ cron: '0 0 * * 0' }] # weekly jobs: retrain: runs-on: ubuntu-latest steps: - run: mlflow run MLProject --env-manager=local
→ Action: Set up MLflow Project spec this week
